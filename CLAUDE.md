# CLAUDE.md — ubx-schema-google

## What this is

The real, published schema snapshot for the Google Cloud provider — a
frozen, versioned `manifest.json` + `members/*.json` group, generated by
`ubx-provider-dynamic --generate-snapshot-group` from Google's own real,
per-product Discovery Documents, committed here (not release-only) so a
reviewer sees the real diff. A `[providers.google]` pin in `ubx` resolves
against this repo's own real GitHub Releases via `provider.AcquireSchema`.
Coordinating repo: `github.com/ubiquex/ubiquex`.

524 real members — one resource-mode and one data-source-mode member per
real, distinct Discovery Document (one merged document per product/version,
unlike Azure's own per-domain-file split).

## Session protocol

1. Read `STATE.md` first — current state only, rewritten not appended.
2. `STATE.md` is rewritten, not appended, as the LAST act of every session.
   Anything that becomes history moves to `HISTORY.md`.
3. Only reference Linear issue IDs given in the handoff prompt; never infer
   one.

## Git rules (strict)

## Repo-specific mechanics

- `.github/workflows/hash-watch.yml` — weekly cron + manual dispatch. Builds
  `ubx-provider-dynamic` from ITS OWN real, latest published release tag (not
  `main` HEAD — an untagged build stamps every regenerated snapshot with the
  meaningless `min_binary_version: "dev"`, UBI-194). Never auto-merges. With
  524 members, expect a real regeneration to touch many `members/*.json`
  files — only real, changed members are ever touched.
- `.github/workflows/publish.yml` — manual dispatch only, refuses to
  republish an existing tag. Verify a real release via `gh api
  repos/Ubiquex/ubx-schema-google/releases/tags/v<version>` after dispatch,
  not the workflow's own exit status.
- Source format is `discovery_docs`, distinct from OpenAPI — a real,
  translated-form convergence still applies (same `internal/schema.Translator`
  as every other source), but the fetch/parse layer is Google's own.
